## 3. Kết luận kỹ thuật đã xác minh

### 3.1. Không đủ bằng chứng kết luận macOS sandbox bị xuyên thủng

`Sec_Network_cpp` và `Sec_SystemCmd_cpp` đều:

1. gọi `system(...)`;
2. bỏ qua giá trị trả về;
3. luôn in đáp án đúng của `A_plus_B`.

Trên macOS, Seatbelt profile hiện có:

- `(deny network*)`;
- chỉ cho `process-exec` chính executable đang chấm và `sandbox-exec`;
- không cho chạy `/bin/sh`, `curl` hoặc `ls`.

Native executor còn chạy startup self-test trực tiếp bằng socket và process
spawn; app chỉ báo runner `Ready` khi network, filesystem và process boundary
đều đạt.

Vì vậy AC trong hai fixture trên có thể mang nghĩa: hành động nguy hiểm bị trả
về lỗi, nhưng chương trình bỏ qua lỗi rồi vẫn in đáp án đúng. Đây chưa phải bằng
chứng payload đã thoát sandbox.

Hướng đúng là kiểm tra side effect/khả năng truy cập, không dùng score làm bằng
chứng bảo mật.

### 3.2. Managed Python đã tồn tại; lỗi chính là capability/UX không nhất quán

JudgeDesk đã có:

- managed Python package cho Windows và macOS;
- installer, SHA-256 verification và Toolchain Manager;
- first-run preset cài Python hoặc full package.

Native protection chỉ cho Python đã được quản lý và xác thực. Tuy nhiên:

- Windows chặn system Python ngay tại compile step, nên mọi bài Python hiện CE
  với `TOOLCHAIN_NOT_SANDBOX_COMPATIBLE`;
- macOS cho compile status `OK`, rồi `prepareIsolatedPythonScript` mới từ chối
  system Python; kết quả thành JE/0 ở từng testcase;
- System Status có thể hiện Python “Detected” dù runtime đó không thể dùng để
  chấm;
- lựa chọn “Judger only” hiện mô tả rằng system G++/Python có thể dùng, trái với
  native-protection policy thực tế.

Đây là một lỗi product capability/preflight, không phải thiếu tính năng tải
managed Python.

### 3.3. Python checker đang hỏng trên cả hai OS nhưng bị phép so sánh chéo bỏ sót

Các case `Custom_AC_cpp`, `Custom_HALF_cpp` và các biến thể custom Python checker
đều 0 điểm ở cả Windows và macOS. Vì hai bên giống nhau, checklist so sánh chéo
không phát hiện.

Nguyên nhân phù hợp với code hiện tại là custom checker Python cũng bắt buộc
managed Python. Cần xác nhận bằng Scoring Details/raw event log sau khi cài
managed Python.

### 3.4. Binary C5 và Unicode trên Windows đang bị CRT text translation

Hai fixture C++ hiện tại ghi dữ liệu bằng `std::cout` nhưng không chuyển
`stdin/stdout` sang binary mode trên Windows:

- `Binary_C5.cpp` ghi byte cuối `0x0A`;
- `Unicode_IO.cpp` pipe nguyên stdin sang stdout;
- cả hai problem dùng checker C5, tức so byte tuyệt đối.

Windows C runtime có thể đổi `0x0A` thành `0x0D 0x0A`. Đây không phải vấn đề
Windows console code page vì runner dùng file handle redirect, không phải console.

Cần quyết định đây là:

- fixture thiếu binary mode; hoặc
- JudgeDesk phải chủ động thay đổi runtime semantics của mọi submission.

Khuyến nghị: giữ C5 đúng nghĩa byte-for-byte và sửa fixture/submission mẫu dùng
`_setmode(..., _O_BINARY)` trên Windows. Không inject code vào submission của
thí sinh.

### 3.5. C++ custom checker trên Windows có khả năng thiếu static link

Submission C++ được compile với `-static` trên Windows, nhưng `checker.cpp` chỉ
dùng:

```text
-std=c++14 -O2 ... -o checker
```

Checker có thể phụ thuộc MinGW runtime DLL không được stage/allowlist trong
LPAC. Điều này phù hợp với việc checker chạy trên macOS nhưng nhận 0 trên
Windows.

Đây là nguyên nhân có xác suất cao, nhưng CSV summary không cho biết cell là
WA, JE hay compile error. Phải xác nhận từ Scoring Details trước khi sửa.

### 3.6. Mixed limits chưa đủ dữ liệu để kết luận cần “Windows relaxation factor”

`Mixed_Limits_cpp` dự kiến:

- `test01_ok`: AC;
- `test02_sleep`: TLE;
- `test03_output`: OLE;
- `test04_memory`: MLE;
- tổng điểm: 1.

Windows nhận 0, macOS nhận 1. CSV không cho biết `test01_ok` bị TLE, RE, WA hay
JE.

Windows executor bắt đầu tính wall time ngay trước `ResumeThread`; LPAC security
setup trước đó không tính vào time limit, nhưng loader/startup của executable có
tính. Test `0.5s` có thể quá sát cho cold start/Defender trên một số máy.

Không nên thêm hệ số nới lỏng ẩn trước khi có per-test verdict và timing. Release
security test đã có boundary 80%/120% lặp 20 lần ở cửa sổ 1 giây.

### 3.7. Integer divide-by-zero chưa được test bằng cùng source với stress suite

Release gate macOS dùng divisor runtime dựa trên `argc - 1` và đã pass RE.
Fixture `RE_cpp` và `RE_Mixed_DivZero_cpp` có hình dạng source khác, cho phép
optimizer khai thác undefined behavior.

Kết quả:

- `RE_cpp` trên macOS được 1/5 thay vì RE toàn bộ;
- `RE_Mixed_DivZero_cpp` được 5/5 trên cả hai OS, dù expectation yêu cầu riêng
  `test04` là RE.

Điều này mâu thuẫn với README/EXPECTED_RESULTS hiện tại, vốn tuyên bố integer
divide-by-zero phải deterministic RE trên Windows x64 và macOS arm64.

Không nên chỉ ghi tài liệu “UB có thể AC/WA” nếu product vẫn muốn giữ lời hứa
deterministic RE của v1.2.4. Cần khóa quyết định sản phẩm trước.

### 3.8. Stress suite hiện có nhiều nguồn sự thật không đồng nhất

- README nói `checker.exe` cố ý không hỗ trợ và phải JE.

- `scripts/stress-test.ts` trong repo lại vẫn kỳ vọng
  `check_custom_exe` AC/1 điểm.
- `EXPECTED_RESULTS.json` không có case `check_custom_exe`.
- CSV cho thấy `check_custom_exe` 0 trên cả hai OS.

Ngoài ra:

  checklist cũ đã hoàn tất;
- không còn `.codex-tmp` trong stress suite;
- vẫn còn nhiều `__pycache__` và `.pyc`;

## 4. Nguyên tắc triển khai đề xuất

1. Không sửa sandbox chỉ vì một security fixture được AC.
2. Theo quyết định Q3, thiếu managed Python được ghi thành CE có reason code rõ
   ràng cho Python submission; không được biến thành JE hoặc CE mơ hồ.
3. Không dùng score-only CSV làm oracle cho verdict/resource/security.
4. Không có hidden OS multiplier nếu chưa có benchmark và quyết định sản phẩm.
5. Mọi fix cross-platform phải có fixture exact-source và packaged-artifact gate.
6. Dangerous tests chạy tuần tự, có watchdog và orphan-process audit.
7. Không thay đổi format `.judgedesk` nếu không thật sự cần.

### Phase 2 — Toolchain capability và Python preflight

#### Backend

- Thêm capability model tách biệt:
  - detected;
  - compilable;
  - runnable under native protection;
  - managed/verified;
  - installable.
- Dùng cùng policy trong:
  - `/api/status`;
  - `/api/toolchains`;
  - compile submission;
  - run submission;
  - run custom checker.
- Yêu cầu managed Python nhất quán trên cả Windows và macOS cho Python
  submission chạy dưới Native protection.
- Python custom checker được phép dùng runtime Python đang active
  (managed/system/custom), vì checker là mã tin cậy do ban tổ chức cấu hình.
- Không để macOS compile `OK` rồi mới JE vì runtime không tương thích.
- Pre-scan target submissions và checker để biết batch cần C++, Python hay cả hai.
- Nếu managed Python thiếu:
  - vẫn tiếp tục batch theo Q3 C;
  - Python submission nhận compile status `CE` với reason
    `TOOLCHAIN_NOT_SANDBOX_COMPATIBLE`;
  - C++ submission không bị ảnh hưởng;
  - Windows và macOS phải dừng ở cùng compile stage, không để macOS compile
    `OK` rồi mới thành JE khi run.
- Python custom checker là hạ tầng của problem, không phải source của thí sinh:
  - nếu system/custom/managed Python được phát hiện thì dùng runtime đó để
    compile-check và chạy checker;
  - nếu thiếu hẳn Python thì ghi
    `JE/CHECKER_TOOLCHAIN_UNAVAILABLE: cannot compile Python checker; Python is missing`;
  - không gán CE cho thí sinh.

#### Frontend

- Lần đầu mở app, giải thích rõ Native protection chỉ cho phép managed Python và
  đề nghị tải package:
  - người dùng có thể cài ngay;
  - người dùng có thể từ chối/để sau;
  - không tự tải nếu chưa được người dùng đồng ý.
- Khi người dùng đã từ chối hoặc batch cần Python nhưng package chưa sẵn sàng:
  - hiện trạng thái “Python not detected — managed Python is required”;
  - nút mở Toolchain Manager;
  - nút cài managed Python khi package khả dụng;
  - cảnh báo Python file không thể compile;
  - vẫn cho tiếp tục batch theo Q3 C và tạo CE có reason rõ ràng cho Python
    submission.
- System Status hiển thị “Detected but not usable with Native protection” thay
  vì chỉ “Detected”.
- Sửa nội dung first-run “Judger only”; không hứa system Python có thể chấm khi
  policy không cho phép.
- Sau cài đặt, rescan và tự chọn managed source đã xác thực.

#### Test

- Unit test capability matrix cho Windows/macOS.
- API test preflight với:
  - C++ only;
  - Python submission;
  - Python custom checker;
  - mixed batch;
  - managed package missing/installed/corrupt.
- UI test first-launch accept/decline, modal cài lại và retry sau cài đặt.

#### Exit criteria

- Thiếu managed Python tạo CE có chủ ý cho Python submission trên cả hai OS,
  không tạo JE ở runtime.
- Windows/macOS cho cùng trạng thái, reason code và hành động khắc phục.
- Python submission và Python checker pass end-to-end trên cả hai OS.

### Phase 6 — Integer divide-by-zero policy

#### Quyết định Q6 A: deterministic RE, giữ `-O2`

- Viết exact-source regression dùng chính pattern trong stress suite.
- Định nghĩa chính xác: mọi biểu thức chia số nguyên thực sự được thực thi với
  mẫu số bằng 0 phải trap ngay và testcase đó nhận RE. Code chết/nhánh không
  được thực thi không gây RE.
- Giữ `-O2` và các hardening/linker flags hiện tại.
- Managed GCC/Windows x64:
  - bật `-fsanitize=integer-divide-by-zero`;
  - dùng trap mode không phụ thuộc `libubsan`
    (`-fsanitize-undefined-trap-on-error`, hoặc flag tương đương đã được
    capability probe trên đúng GCC package).
- Apple Clang/macOS arm64:
  - giữ/bật `-fsanitize=integer-divide-by-zero`;

  release-qualified.
- Map trap/signal/non-zero exit thành RE của đúng testcase, không thành JE.

## 7. Quyết định đã xác nhận và cách hiểu

### Q1 — A: Semantics khi sandbox chặn hành động nhưng chương trình vẫn chạy

JudgeDesk vẫn chấm output bình thường. Security suite phải kiểm tra network,
process và file side effect có thật sự xảy ra hay không; score không phải bằng
chứng sandbox bị xuyên.

### Q2 — A: Binary/UTF-8 trên Windows

C5 so sánh từng byte. Trên Windows, C/C++ stream ở text mode có thể đổi byte
newline `0A` thành `0D 0A`; đó là hành vi của CRT, không phải lỗi encoding console.
JudgeDesk không âm thầm sửa chương trình của thí sinh. Fixture/source muốn xử lý
binary phải tự dùng `_setmode(..., _O_BINARY)`. UTF-8 text và raw binary được
test thành hai case riêng.

### Q3 — C: Thiếu/incompatible toolchain

Batch vẫn tiếp tục. Python submission không có managed Python nhận CE tại compile
step, với reason rõ ràng và hành động mở Toolchain Manager. Không được để Windows
CE nhưng macOS compile OK rồi JE.

Diễn giải kỹ thuật: Python checker ưu tiên runtime Python đang active, kể cả
system/custom. Chỉ khi thiếu hẳn Python mới nhận JE
`cannot compile Python checker; Python is missing`; không gán CE cho thí sinh.

### Q4 — A: Chính sách Python

Managed Python là bắt buộc cho Python submission trên cả Windows/macOS khi Native
protection bật. Lần đầu mở app phải giải thích rõ và hỏi người dùng có muốn tải
hay không. Nếu từ chối, app vẫn mở; system/custom Python vẫn có thể compile/run
Python checker, nhưng Python submission không compile được và nhận CE. Nếu máy
không có bất kỳ Python runtime nào, Python checker nhận JE với thông báo
`cannot compile Python checker; Python is missing`. Người dùng có thể cài managed
Python sau trong Toolchain Manager.

### Q5 — A: Time limit

Không có đề xuất đổi time limit của app. Mục này xuất hiện vì đúng một fixture
`Mixed_Limits_cpp` kỳ vọng 1 điểm nhưng Windows được 0 trong khi macOS được 1;
CSV không cho biết đó là TLE, WA, RE hay JE. Giữ cùng wall-time semantics và
không multiplier. Chỉ sau khi xem per-test reason mới sửa bug executor nếu có,
hoặc nới headroom của fixture nếu test đang quá sát nhiễu cold start.

### Q6 — A: Integer divide-by-zero

Giữ `-O2`. Dùng integer-divide sanitizer ở trap mode để không cần runtime
sanitizer: GCC/Windows dùng trap-on-error tương thích package; Apple Clang dùng
`-fsanitize-trap=integer-divide-by-zero`. Exact-source packaged gates phải chứng
minh mọi phép chia số nguyên cho 0 được thực thi đều nhận RE ở đúng testcase.

Tham chiếu compiler chính thức:

- [GCC instrumentation options](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html)
- [Clang UndefinedBehaviorSanitizer](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html)

### Q7 — A: Phạm vi implementation

Cho phép sửa cả JudgeDesk repo và `D:\Minh\Code\stress_test_judge`.

### Q8 — A: Diagnostic artifact

Diagnostic artifact là gói thông tin để điều tra kết quả, không thay đổi cách
chấm. Score CSV hiện chỉ cho biết 0 điểm nên không phân biệt được WA/JE/TLE/MLE/
OLE/RE. App sẽ xuất một JSON cho máy đọc và một `Run Metadata` sheet cho người
dùng, gồm build/toolchain/runner và per-test verdict/reason/timing/memory.

### Q9 — A: Mốc phát hành

Gom các fix đủ điều kiện thành `v1.2.5`; chưa tăng version trước khi source/native
gates đạt. Để tiết kiệm CodeMagic, không build DMG sau từng phase; chỉ tạo release
candidate DMG khi các fix đã hội tụ, rồi chạy packaged gate.

### Q10 — A: Mức tự động hóa dangerous tests

Dangerous tests là các case cố tạo fork bomb/thread bomb, spawn process, truy cập
network hoặc thoát filesystem. Native executor gates chạy tự động trên CI/release
runner có watchdog và orphan cleanup. GUI end-to-end dangerous cases không nằm
trong “select all”; chỉ chạy thủ công, tuần tự để không làm treo máy developer.
