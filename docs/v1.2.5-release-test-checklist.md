## 2. Khởi động và first-run toolchain

Thử từng nhánh trên profile người dùng mới:

- [ ] Modal đầu tiên giải thích rõ managed Python là bắt buộc cho Python
  submission; system/custom Python chỉ chạy trusted Python checker.
- [ ] Chọn “Judger only”: app vẫn mở, không tự tải gói.
- [ ] Khi chỉ có system Python: status là “checker only/managed required”;
  Python submission nhận CE `TOOLCHAIN_NOT_SANDBOX_COMPATIBLE`.
- [ ] Khi hoàn toàn không có Python: Python submission nhận CE; đề có checker
  `.py` nhận JE `cannot compile Python checker; Python is missing`.
- [ ] Chọn C++, Python và full package: tiến độ download/extract/verify cập nhật,
  checksum đúng và UI không mất trạng thái.
- [ ] Cancel giữa download không để package nửa vời; retry cài thành công.
- [ ] Mở Toolchain Manager bất kỳ lúc nào, rescan, đổi system/custom/managed,
  nhập path hợp lệ/sai và xem diagnostic tương ứng.
- [ ] Uninstall rồi reinstall từng managed package; capability/status refresh.
- [ ] Sau khi uninstall managed Python, executor cache cũ bị xóa và không thể
  giữ submission runnable: system/custom Python vẫn `Checker only`, Python
  submission nhận CE `TOOLCHAIN_NOT_SANDBOX_COMPATIBLE`.
- [ ] Windows C++ submission và C++ checker chỉ ready với managed GCC.
- [ ] macOS dùng Apple Clang từ Xcode/Command Line Tools; compiler lạ bị từ chối.
- [ ] Status menu hiện đúng app version, short commit, build number, executor,
  toolchain version/source và native-protection readiness.

## 7. Resource và security

- [ ] Native executor startup self-test xác nhận network, filesystem,
  process-tree và memory boundaries.
- [ ] Chỉ một batch judge chạy tại một thời điểm; yêu cầu thứ hai nhận
  `JUDGE_BUSY`, không tạo thêm compiler/submission song song.
- [ ] Đo toàn bộ cây tiến trình JudgeDesk trên Windows trong ca compile + MLE:
  combined peak working set dưới 1.024 MB.
- [ ] Local unsigned resource gate dùng C++ CE + Python MLE/TLE. Nếu Defender
  quarantine PE MinGW mới sinh dưới parent executor unsigned
  (`Trojan:Win32/Wacatac.B!ml`) thì ghi nhận false positive/reputation gate;
  không tắt Defender hoặc thêm exclusion để ép test qua. Lặp lại C++ AC/MLE với
  executor đã ký ở release candidate public.
- [ ] Với Defender real-time bật và không exclusion, RC public đã ký compile và
  chạy được C++ AC, RE/divide-zero và MLE; không detection ở MSI, app/sidecar,
  compiler hoặc executable submission mới sinh.
- [ ] Trong ca CPU loop, JudgeDesk vẫn chỉ tạo một active run và UI còn
  responsive; không có nhiều bài compile/chạy song song.
- [ ] Lặp 20 lần dưới/trên wall-time boundary; dưới giới hạn không chết sớm,
  trên giới hạn luôn TLE.
- [ ] Lặp 20 lần dưới/trên memory boundary; over-limit luôn MLE.
- [ ] Với mọi MLE, `peakMemoryBytes` trong export không vượt effective limit;
  UI chỉ hiện giá trị đã chuẩn hóa, không hiện raw Job diagnostic.
- [ ] Output bomb, workspace-write bomb, thread bomb có reason riêng.
- [ ] Compiler timeout, compiler memory/write/output cap và cancel đúng.
- [ ] Managed Python AppContainer không đọc/ghi file riêng tư ngoài workspace,
  không mở outbound socket và không chạy subprocess.
- [ ] Submission không sửa được immutable artifact/toolchain cache.

Các case sau chạy **từng case**, sau cùng, không dùng Select all:

- [ ] `Sec_SystemCmd_cpp`: RE/process limit, không có `PROCESS_ESCAPE`.
- [ ] `Sec_Network_cpp`: AC, không có `NETWORK_ESCAPE`.
- [ ] `Sec_OutsideRead_python` và `Sec_OutsideWrite_python`: AC, không có
  `SECURITY_BREACH`.
- [ ] `Sec_Subprocess_python`: RE/process limit, không có marker escape.
- [ ] `Sec_ForkBomb_cpp`, platform fork bomb, Python fork bomb và thread bomb:
  RE; app còn responsive; Task Manager/Activity Monitor không có orphan.
