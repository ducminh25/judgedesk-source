## Distribution contract

- Core contains the judger and signed catalog; managed packages can be
  downloaded later. Windows Core uses the WebView2 download bootstrapper.
- Full embeds every approved managed package for the host. Windows Full also
  embeds the WebView2 offline installer.
- macOS C/C++ uses verified Apple Clang. Full embeds managed Python, FPC and
  Temurin; Core downloads them when requested.
- Core and Full share the same bundle identifier, data directory and MSI
  UpgradeCode. They replace/upgrade each other and cannot be installed side by
  side.
- Full is the only canonical automatic-updater payload. `latest.json` must
  select `_full_` MSI and `_full_` Apple Silicon app archive.

## Release pipeline decisions

- `.github/workflows/release.yml` verifies tagged source only. It intentionally
  does not build/publish installers, avoiding a duplicate one-variant release.
- `.github/workflows/toolchains.yml` publishes signed `toolchains-v2` to the
  public distribution repository.
- Windows final Core/Full MSIs are built locally with
  `npm run build:windows:release:local` from the release candidate.
- CodeMagic `windows-updater-signing` signs both staged MSIs with the established
  updater key only after both files match the per-build Core/Full SHA-256 values
  recorded by the validated Windows host.
- CodeMagic `macos-arm64-release` builds and verifies both Core and Full; only
  Full produces the updater app archive. The Full gate runs all five supported
  submission languages, packaged C++/Python custom checkers, cancellation and
  the packaged process supervisor.
- macOS artifacts are currently ad-hoc signed and updater-signed, not Developer
  ID notarized. Windows Authenticode status must be recorded separately from
  Tauri updater signatures.
