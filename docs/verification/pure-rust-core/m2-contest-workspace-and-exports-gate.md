## 1. Executive Summary & Sub-Slice Closure

Macro-Milestone 2 (`M2`) delivers complete Pure Rust Core (`crates/judgedesk-core`) parity for Phase 6 (`WP6.1a`, `WP6.1b`, `WP6.1c`, `WP6.2`, `WP6.3`, and `G6` — Contest Workspace, OSD Daemon, Import/Export & Lifecycle) across five ordered TDD sub-slices:

1. **Sub-slice `M2.1` (`WP6.1a` — OSD Parser, Durable Source Claim, Staged Snapshot & Themis Web `.log` Writer):**
   - Implemented `parse_osd_filename` and `is_safe_osd_component` in [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) supporting both dotted (`1650000000[HS01][SUM].cpp`) and dotless Themis Web (`0[HS01][SUM]cpp`, `0[HS01][SUM]c`, `0[HS01][SUM]py`, `0[HS01][SUM]pas`, `0[HS01][SUM]java`, `0[HS01][SUM]sb3`) filenames across all 6 release languages (`C++`, `C`, `Python 3`, `Pascal`, `Java`, `Scratch .sb3`), while rejecting path traversal (`.`, `..`, `/`, `\`), Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`), control characters, trailing dots/spaces, and the Themis bullet separator (`‣`, `\u{2023}`).
   - Implemented durable source claiming (`claim_osd_source_file`, `wait_for_claimed_source_stability`, `stage_claimed_source`, `verify_claimed_source_integrity`, `dispose_claimed_source`) with a 16 MiB file size ceiling (`MAX_OSD_SOURCE_BYTES`), symlink/reparse-point/hardlink (`nlink == 1` on Unix) rejection, SHA-256 snapshot verification, and explicit leaf-only disposal without recursive `remove_dir_all` on untrusted trees.
   - Implemented `format_rational_decimal` with exact `BigUint` half-up rounding in [`crates/judgedesk-core/src/rational.rs`](../../../crates/judgedesk-core/src/rational.rs) and `write_osd_log` / `write_osd_error_log` in [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) producing CRLF (`\r\n`) UTF-8 `.log` files formatted to exact 6-decimal precision (`HS01‣SUM: 3.333333`, `HS01‣SUM‣Test01: 3.333333`, `Thời gian ≈ 0.042000 giây`, `ℱ` error headline prefix).
2. **Sub-slice `M2.2` (`WP6.1b` — OSD Watcher, Debounce, Latest-Job-Wins & Serial Queue):**
   - Implemented `OsdService`, concurrent inbox scanner (`scan_osd_inbox_once`) and serial queue worker (`process_osd_queue`), `InFlightClaimGuard`, `$History` archiving, case-insensitive contestant alias collision detection (`has_case_insensitive_alias_collision`), per-job isolated `OwnedWorkspace::create_in_temp("osd_job")` staging, and `latest_jobs` (`(contestant, problem)` $\rightarrow$ `job.id`) tracking in [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs).
3. **Sub-slice `M2.3` (`WP6.1c` — OSD HTTP Routes, SSE Stream & Graceful Stop/Drain):**
   - Implemented `GET /api/osd/status`, `POST /api/osd/start` (including `problemConfigs` support and active/queued/in-flight session switch protection), `POST /api/osd/stop`, and `GET /api/osd/events` (`text/event-stream` SSE stream with initial `osd_status` snapshot, `RecvError::Lagged` recovery, and `tx.closed()` disconnect cleanup) in [`crates/judgedesk-core/src/server/routes/osd.rs`](../../../crates/judgedesk-core/src/server/routes/osd.rs).
   - Wired `state.osd.stop()` and `JudgeJobRegistry` lease cancellation into `POST /api/shutdown` in [`crates/judgedesk-core/src/server/routes/system.rs`](../../../crates/judgedesk-core/src/server/routes/system.rs).
4. **Sub-slice `M2.4` (`WP6.2` — Workspace/Problem Discovery, UTF-8 Preview & Polygon Config Routes):**
   - Hardened `GET /api/fetch-contestants`, `GET /api/fetch-problems`, `GET /api/fetch-tests`, `GET /api/fetch-polygon-tests` (requiring `problem` query parameter and truncating 35-byte input previews cleanly at valid UTF-8 codepoint boundaries via `std::str::from_utf8` / `Utf8Error::valid_up_to()` without emitting `U+FFFD`), and `GET`/`POST /api/polygon-config` (persisting normalized `compile` configuration into `Config.cfg`) in [`crates/judgedesk-core/src/server/routes/discovery.rs`](../../../crates/judgedesk-core/src/server/routes/discovery.rs).
5. **Sub-slice `M2.5` (`WP6.3` & `G6` — Binary Score Export `/api/open-excel` & Phase 6 Exit Gate):**
   - Implemented `POST /api/open-excel` (`application/vnd.judgedesk.score-export-v1`, 256 MiB route body limit, `JDXLSX01` magic header, little-endian `u32` diagnostic JSON length, UTF-8/JSON validation, non-empty workbook payload check, isolated `<TEMP>/judgedesk/exports/<UUID>/{Book.xlsx,diagnostics.json}` write, and `openMode` response) in [`crates/judgedesk-core/src/server/routes/export.rs`](../../../crates/judgedesk-core/src/server/routes/export.rs) and [`crates/judgedesk-core/src/server/os_integration.rs`](../../../crates/judgedesk-core/src/server/os_integration.rs).

## 3. 5-Axis Adversarial Code Review Summary & Dispositions

A fresh-context 5-axis adversarial review (Functionality, Quality, Security, Performance, Maintainability) was conducted via an independent subagent (`6fc82af3-a2e1-46c4-b96c-f76e42cd7a79`) across all `M2` files in `crates/judgedesk-core`. All 14 findings (`#1`–`#14`) were resolved in-place prior to running the final verification union:

| Finding ID | Axis | Location | Summary | Disposition |
|---|---|---|---|---|
| `P0-1` | Functionality / Security | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) | `process_osd_queue` passed the shared `Contestants` root to `run_judge_session` instead of the job's immutable `staged_path`, and `spawn_osd_watcher_loop` serialized inbox scanning and judging in a single loop. | **RESOLVED:** Decoupled inbox scanning (`scan_osd_inbox_once`) and queue execution (`ensure_osd_queue_worker_spawned` / `process_osd_queue`) into concurrent tasks, and staged each job's verified `staged_path` bytes into an isolated per-job `OwnedWorkspace::create_in_temp("osd_job")`. |
| `P0-2` | Security / DoS | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) | Unbounded `fs::read` on untrusted files in the LAN-writable OSD inbox could cause host OOM if a multi-GB file was dropped. | **RESOLVED:** Enforced `MAX_OSD_SOURCE_BYTES = 16 * 1024 * 1024` (16 MiB) in `verify_regular_unlinked_file` before any read or staging allocation. |
| `P0-3` | Concurrency / Safety | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) | `OsdService::start` only checked `guard.status.active && (current_job.is_some() || !queue.is_empty())`, allowing a session switch while a stopped session was still draining or claiming a file. | **RESOLVED:** Added `InFlightClaimGuard` (`in_flight_claims`) and refused `start()` whenever `current_job.is_some() || !queue.is_empty() || in_flight_claims > 0`, regardless of `status.active`. |
| `P1-4` | Functionality | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs), [`crates/judgedesk-core/src/server/routes/osd.rs`](../../../crates/judgedesk-core/src/server/routes/osd.rs) | Missing `osd_contestant_added` SSE event when creating a new contestant directory, and `problemConfigs` in `POST /api/osd/start` was ignored. | **RESOLVED:** Emitted `osd_contestant_added` when `!contestants_dir.join(&contestant).exists()` before creation, and threaded `problemConfigs` from `OsdStartPayload` into `OsdService::start` and `merge_problem_config` in `process_osd_queue`. |
| `P1-5` | Functionality | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) | `JE`/`FAIL` results emitted `osd_problem_completed` instead of `osd_job_failed`, and integrity/interactive/0-testcase/stream errors did not emit `osd_job_failed`. | **RESOLVED:** Checked integrity, interactive mode, and testcase count before judging, plus `JudgeStreamEvent::Error` and `JE`/`FAIL` status after judging; wrote error logs (`"Lỗi hệ thống chấm"`) and emitted `osd_job_failed`. |
| `P1-6` | Reliability / SSE | [`crates/judgedesk-core/src/server/routes/osd.rs`](../../../crates/judgedesk-core/src/server/routes/osd.rs) | `handle_osd_events` exited on `RecvError::Lagged` and did not observe `tx.closed()` while idle. | **RESOLVED:** Used `tokio::select! { _ = tx.closed() => break, recv_res = sub.recv() => ... }` and recovered from `RecvError::Lagged` by emitting a fresh `osd_status` frame. |
| `P1-7` | Reliability | [`crates/judgedesk-core/src/osd/mod.rs`](../../../crates/judgedesk-core/src/osd/mod.rs) | Transient stability or staging failures silently unlinked `.incoming` without preserving the submission or emitting `osd_error`. | **RESOLVED:** Added `preserve_rejected_incoming` to save `.incoming` into `Rejected/`, wrote an error log when `enable_log` is active, and emitted `osd_error` before `dispose_claimed_source`. |

| `P2-10` | Contract Parity | [`crates/judgedesk-core/src/server/routes/discovery.rs`](../../../crates/judgedesk-core/src/server/routes/discovery.rs) | `handle_fetch_polygon_tests` did not require the `problem` query parameter. | **RESOLVED:** Returned `400 PATH_REQUIRED` when `q.problem` is missing or empty. |
